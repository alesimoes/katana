L6Codegen

Unified Code Generation Engine (codegen): a short code spec (.kcode, text or JSON) becomes code in several languages through the typed AST (UIR-H) and the CFG in SSA form (UIR-G), with no text templates; Python, JS/TS, C and Go backends are built. The model writes the spec, the engine generates the code. The sources are now #included by src/katana.c (warnings silenced), but nothing in the agent calls them.

L4UIOE

The layer before the model, in C, no model call: Interpret, Classify, Route, Retrieve, Orchestrate, then a Context Builder that appends one [katana: context for this request ...] block (at most 1500 tokens) to the user turn. Greetings, vague requests, exact-file requests, low-confidence retrieval and deadline overruns get no block. It receives the request and the URLs typed in it (an attached image goes to the vision projector, not here), the entities found in the text (symbols, paths, folders, quoted text, error text, config keys, env vars, dates, amounts), the working folder and index roots, the state of the code index, the session state (open investigation, ranges already shown, open todo steps), agent memory as dated evidence, and re-reads files from disk to verify its evidence. The Find and Symbols facades answer through the same engine only with KATANA_UIOE=full. KATANA_UIOE=pack is the default; off disables it.

Request paths

  • Text request. User input (console, desktop, -p, server) to UIOE (interpret, classify, route, retrieve over the code index) to the context block or nothing to the model on Vulkan or CPU, which answers or emits a tool call (grammar-constrained, sampled) to the tool, whose result returns as data, repeated until a text answer; the answer streams back to the app.
  • Image request. A view PNG attached, the agent or the desktop writes a brief, Render with stable produces the preview, the user approves, Render with flux produces the final image.
  • Code request, today. The model reads with Find and Symbols, changes code with Edit by symbol, validated before the write.
  • Code request, planned. The model writes a spec; codegen parses it to UIR, checks it, builds the AST, renders the language, validates it; the result goes in through Edit by symbol. The codegen half does not exist in the agent yet.

Glossary

UIOE
Unified Intelligence Orchestration Engine: the layer that runs before the model (src/uioe/, docs/uioe.md), in C with no model call, to understand a request and gather evidence. Modes: pack (default), full, off.
Interpret
reads the request: entities (symbols, paths, folders, quoted text, error text, config keys, URLs, dates), what is asked, and the risk.
Classify
decides the domain (code, files, data, research, memory, system, chat), the kind of question (locate, usage, impact, how-to, overview, error, flow) and how hard it is.
Route
chooses which sources can answer (code index, files, memory, web registry) and which cannot, and says why one was left out.
Retrieve
runs the queries through the engine behind Find and Symbols, re-reads the files to verify what it found and builds the evidence graph.
Orchestrate
sequences the steps and respects the deadline (KATANA_UIOE_MS, KATANA_UIOE_TOTAL_MS).
evidence graph (UG_*)
the graph retrieval builds: nodes are files, line ranges, symbols, keys, documentation lines and facts; edges are calls, definitions, uses, imports, sends, handles, links, contains, mentions. UG_* is the prefix of its limits and of the decision below.
decision (UG_NONE, UG_LIMITS, UG_PACKET)
what the UIOE does with the result: UG_NONE injects nothing (greeting, vague request, low confidence, deadline overrun); UG_LIMITS injects only "not found / limits" plus the next step; UG_PACKET injects the full block.
context block (packet)
the [katana: context for this request ...] text appended to the user message, at most 1500 tokens; the system prompt does not change, so the prefix cache stays valid.
facades
Find and Symbols answered by the same UIOE state, so what the block already showed is not repeated by a tool call.
Unified Code Generation Engine (codegen)
turns a short code spec (.kcode, text or JSON) into code in several languages through a typed AST (UIR-H) and a control-flow graph in SSA form (UIR-G), with no text templates. Python, JS/TS, C and Go backends are built; not yet connected to the agent.
UIR-H / UIR-G
codegen's typed AST (H) and its CFG in SSA form (G).
.kspec
LoRA-style specialization adapter; .kcode is a code spec, a different file.
brief
the one-line text prompt the Render tool sends to the image engine.
expert cache
MoE experts in VRAM slots by heat; cold experts run on the CPU from the mapped file.

  • Whether the UIOE, the tool set, the grammar, the sampler or the index improve the real model's answers is unknown: no Qwen3.6 measurement of them is recorded.
  • Windows was not built after the recent work. Specialization and codegen were judged from code and notes; the codegen tests were not re-run.
  • Some older notes still carry stale status lines (for example the code-index design note and the embedding notes).
